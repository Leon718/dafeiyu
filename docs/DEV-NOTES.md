她不是助手，是室友。

**她不住在桌面上。** 你在 WorkBuddy 里打开「大肥鱼」那个空间跟她说话，她才出现；
几分钟没人理，她淡出、窗口整个隐藏，桌面上不留任何东西。她偶尔也会在你干活时
自己冒一句——说完就走，不赖着。

你干活的时候她不播报进度，也不做「思考中 / 写入中」的表情。那种东西看三次就腻。

> 这一版是形态三：**被召唤才出现**。前两版（表情跟着 agent 状态走 / 常驻右下角）已废弃，见文末留档。

## 怎么启动

**不用启动。** 你正常干活就行——hooks 会在需要她的那一刻把她唤醒（后台，不阻塞 agent）。

手动叫醒她：`npm start`（它去问安装器要宿主自带的那份运行引擎，仓库里不装 Electron）。
（旧版有个 `接她回家.command` 双击启动器，已随目录重构去掉 —— 现在安装器会负责拉起，手动启动只为调试）。

## 她的生命周期（形态三的核心）

```
agent 事件到达 ──► 桥看端口文件
                    ├─ 有：把事件投给她（后台，1ms 级）
                    └─ 无：拉起她 + 排队补投这条事件（不丢）
                              │
                              ▼
                    桌宠进程（隐藏，不占桌面）
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   她在她家说话          她觉得值得开口          你戳她/拖她
   （cwd 命中她家）      （失败 7 次、深夜…）      （手动召唤）
        └─────────────────────┴─────────────────────┘
                              ▼
                        淡入出场 420ms
                              ▼
                20 秒没人理（可调）→ 淡出 720ms → 窗口隐藏
                              ▼
                    20 分钟没人理 → 进程退出（不常驻占内存）
```

| 行为 | 默认 | 怎么改 |
|---|---|---|
| 最后一次互动后多久退场 | **20 秒** | 右键 →「停留时间」：5 秒 / 10 秒 / 20 秒 / 1 分钟 / 3 分钟 |
| 她自己跳出来多频繁 | **标准** | 右键 →「活跃度」：静默 / 标准 / 高 |
| 多久没人理就退出进程 | 20 分钟 | `config.json` 的 `presence.quitAfterMs` |
| 淡入 / 淡出 | 420 / 720ms | `presence.fadeInMs` / `fadeOutMs` |

停留时长存在 `~/Library/Application Support/dafeiyu/pet-prefs.json`，
改完立刻生效（不用等她下次出场），重启也记得。

> 一个例外：**她正在说话时不会被掐断**。渲染层会把这一串话的时长报给主进程，
> 退场倒计时自动往后延。否则你选了 5 秒，那句长话还没看完人就没了。

> 退场是**真的 `win.hide()`**，不是把透明度调成 0。
> 透明度 0 的窗口还在原地挡点击，那等于她人走了影子还站着。

## 怎么玩


| 操作 | 反应 |
|---|---|
| 单击 | 她理你一下（动作 + 一句，通常很不客气） |
| 双击 | **跟她聊聊**：直接跳回你俩的会话；还没认出会话就把 `~/WorkBuddy/dafeiyu` 打开 |
| 按住拖动 | 悬空姿势跟着走，松手落地，会骂你 |
| 右键 | **活跃度** / **停留时间** / 大小 / **积分累计使用** / 跟她聊聊 / 退出 |

关于右键菜单的取舍（`ACTIVITY_LEVELS` 在 `main.js`，`muted` 在 `hook-mapper.js`）：

- **活跃度**取代了原来的「减少动态」。三档同时拧三个旋钮：主动开口的小时预算与冷却、
  深思（唯一花钱的一层）的预算、她自己的日子还演不演。静默 = `detector.muted = true` +
  `gate.maxPerHour = 0`：她自己不出来，但「你叫她」的时刻（点播、在她家说话）照常应 ——
  判断在 `handle()` 的最后一道，所以她照样看得见你干了什么，静默的是嘴不是眼睛。
- **撤掉「回到右下角」**：救急的作用改到启动时自动做（`loadWindowState` 会检查上次的坐标
  还在不在一块真实屏幕上，拔了外接屏就自己回主屏右下角）。
- **撤掉「打开 WorkBuddy」**：双击她就能回去，同一个动作不留两个入口。
- **「减少动态」不再进菜单**：`reducedMotion` 仍然生效（手改 `pet-prefs.json`），
  只是位置让给了活跃度 —— 菜单是给「她多吵」用的，不是给「我身体不好」用的。

## 她的家在 `~/WorkBuddy/dafeiyu/`

桌宠只是她的**脸**。她的为人、说话方式、记忆都在那个目录里：

```
~/WorkBuddy/dafeiyu/
├── AGENTS.md          # 她是谁（人格+记忆约定+桌宠约定）。**会话第一轮自动注入**，唯一来源
├── voices.json        # 她的台词库（桌宠读这个）
└── .workbuddy/memory/
    ├── MEMORY.md      # 她的结论（每轮都注入，≤1 万字）：你什么脾气、在折腾什么、何时闭嘴
    ├── 2026-10-26.md  # 她的日记（不注入，按需读）：一行一条，桌宠替她抄
    ├── 他的票.md       # 冷区：需要时才翻
    └── archive/       # 30 天前的日记按月归档
```

**第一次用（关键，只有一次）**：她必须在 WorkBuddy 里有**至少一个任务**，否则左侧「空间」里不会出现她。

侧栏的本质是「**按文件夹分组的任务列表**」——文件夹里一个任务都没有，就不会有条目。所以：

1. 点「新建任务」
2. 点输入框左下角的「**选择工作空间**」，选到 `~/WorkBuddy/dafeiyu`
3. 随便说一句（「在吗」）发出去

之后 hook payload 里带 `cwd`，她一旦在自己的目录里见到会话就把 session 记下来，
再双击她就能直接回到那个会话。没记住之前，双击只会打开目录——她会告诉你「我家在……你去那儿说一句」。

> 排查过的一个弯路：侧栏**不是**从 `~/.workbuddy/workbuddy.db` 的 `workspaces` 表读的。
> 那张表里有她的目录也没用（亲测：写进去了，侧栏照样看不到）。
> 真正的来源是 `sessions` 表按 `cwd` 分组，没有 session 就没有条目。


## 她什么时候说话

她按「**时刻**」开口，不按状态。每个时刻有自己的门槛，还会被两道总闸卡住：

| 时刻 | 触发条件 | 她说什么 |
|---|---|---|
| `danger` | 要跑一条**回不去**的命令（rm -rf ~ / 通配符 / .git / reset --hard / clean -fdx / push -f / DROP） | 停。 → 那个目录里有什么，你说得出来吗。 |
| `flip` | 上一次是 A 种错，这一次换成 B 种（15 分钟内、同一个项目） | 不是{a}了。 → 是{b}。 |
| `rush` | 同一条命令失败后 15 秒内又跑，还是红的 | {s} 秒。 → 它没看上一屏。 |
| `loop` | 改→跑→改→跑 交替到第 3 轮 | 它改，它跑，它改。 → 第 {n} 轮了。 |
| `grind` | 同一个文件半小时里改到第 3 / 5 / 8 次 | {f} 第三遍。 → 它没换个地方想。 |
| `guess` | 同一条命令跑到第 3 / 5 遍 | {c} 第三遍。 → 它以为这次会不一样。 |
| `errKnown` | 失败时她认得出错误类型（8 类） | 又是找不到包。 → 它装的那个环境，不是它跑的那个。 |
| `blast` | 一轮里动了 6 个以上文件 | 它一轮动了 {n} 个文件。 → 改完它自己记得住哪个是哪个吗。 |
| `noVerify` | 一轮里改了 4 个文件，却一次都没跑过 | 它改了 {n} 个文件。 → 一次都没跑。 |
| `searchOnly` | 连着翻 12 次、跨 4 个以上不同地方、一行没写 | 它翻了 {k} 个地方。 → 一行没写。 |
| `stall` | 单条命令挂了 5 分钟才回来 | {c} 跑了 {m} 分钟。 → 它还没回来。 |
| `reportBack` | **他不在的时候**（两次说话隔 8 分钟以上），它干了事 | 它刚才 {c}。 → 我喊了一声，你不在。 |
| `firstGreet` | 当天第一次见到你 | 来了。 → 我盯着呢。 |
| `comeback` | 消失 30 分钟以上又出现（期间没什么事发生） | 嗯。 → {m}分钟。我不问你去哪了。 |
| `lateNight` | 23:30 之后，**一夜只提一次** | {clock}了。 → 它不会累，你会。 |
| `repeatedFailure` | 同一轮失败到 3 / 5 / 7 次，分档 | 它 {n} 次了。 → 同一个地方。 |
| `successAfterStruggle` | 失败过两次之后终于成了 | 成了。 → 第 {n} 次。 |
| `longRun` | 一轮干超过 20 分钟 | 它跑了 {m} 分钟。 → 还没完。 |
| `idleLong` / `selfTalk` | 静了 15 分钟以上，低概率 | 还在吗。 |
| `thought` | 她攒着想说的话到点了（见下节） | 那个还没结论的事，你昨晚也在想它。 |
| `poke` / `drag` | 你戳她 / 拖她 | 别戳。 / 放我下来。 |

前八个是「她看见你了」这一类，见下面单独一节。它们排在最前面——因为
「又熬夜了」任何 AI 都能说，`agent.py 第三遍`只有坐在旁边的人数得出来。

两道总闸（`config.json` 的 `gate`）：

- **一小时最多主动打扰十二次**——过了就不说了，等下一个小时。
  这是兜底：真正的防话痨是每类观察自己的去重窗口（见 `watch` 那节）。
- **两次主动之间至少隔 60 秒**——所以她不会跟着你的失败次数一路念。

> 四个刻意的例外：
> - **`reportBack` 里的危险那一族也不占额度、不吃冷却**（见下节）。
>   它跟当场那句「停」是同一件事的两个半截：他当时没听见，现在补上。
>   被限流吞掉，等于它趁他不在干的事没人知道。
> - **回应类不占额度、也不吃冷却**（`FREE_MOMENTS`：见面礼、你回来了、你戳她、拖她、在她家开口）。
>   早期版本（1）给她「一轮最多两句」，结果开局那句「来了。」吃掉一个名额，
>   到第 7 次失败她想说「我不数了」时已经没额度了；（2）更糟的是闸门对所有时刻都生效，
>   于是 4 分钟冷却内戳她**只有动画没有台词**——屏幕上看起来就像气泡坏了。
> - **`danger` 连额度都不占**（`NO_BUDGET`）。一个月只该出现几次，但如果真出现十几次，
>   该被限流的是她的点评，不是她的「停」。排队等于：你按下回车之后她才说「别按」。
> - **`rush` 不吃冷却**（`NO_COOLDOWN`）。它针对的就是「刚说完你就重跑」，
>   被 60 秒冷却吞掉等于这句永远说不出来。
> 单测 `[14]` 守着回应类那条，`[16]` 守着 danger 和 rush 两条。

气泡本身：15px 字号、最宽 300px、最短停留 4.2 秒、出现时带一点弹入。
她说完一句就消失，所以别指望事后还能看到——那不是聊天记录，是口气。

## 他不在的时候，她替你盯着（`reportBack`）

这是等待场景里她最值钱的一句。

真实用法是：**他说一句需求，然后等着。操作全是他雇的那个 agent 做的。**
这件事带来两个后果，一起把「实时播报」这条路堵死了：

1. **他不在屏幕前** —— 她喊的话他听不见；
2. **他不知道自己走了多久** —— 「你回来了」是废话，他知道自己回来了。

所以她改成**记账**：从他上次提问到这次提问，一本账记着期间发生了什么
（`watch.js` 的 `ledger`：碰过几个文件、跑过几条命令、红过几次、出过几种错，
以及它想干过哪些回不去的事）。他下一次开口时结算，说一句。

判据在 `config.json` 的 `gate`：`reportBackMinMs`（8 分钟）+ `reportBackMinActs`（3 个动作）。
短于 8 分钟说明他根本没离开，汇报就成了播报。

危险那一条分三族说，因为三种情况的分量完全不同：

| 子类 | 什么时候 | 她说 |
|---|---|---|
| `dangerRan` | 它真跑了（exitCode 0） | rm .ssh。 → 它干了。你要不要看看。 |
| `dangerBlocked` | 没跑成 | 它想 {c}。 → 后来没跑成。 |
| `dangerUnknown` | 没等到结果 | 它刚才要 {c}。 → 后来跑没跑，我不知道。 |

**她看得见 exitCode，所以这三句是事实，不是猜的。**

三个取舍，都是踩出来的：

- **危险那一族免冷却、免预算**（`must`），也不受「至少 3 个动作」限制 ——
  它就算只干了一件回不去的事，也比干了十件寻常事更该说。
- **喊不出来也要记**：`_cue` 的去重和冷却可能把当场那声「停」吞掉，
  但 `ledger.dangers` 照记。他不在时那一声本来就白喊了，账再不记就等于没发生过。
- **打招呼让位给危险**：隔夜回来的第一句本该是「来了」，
  但如果它趁他不在干了回不去的事，先说事 —— 打招呼晚一句不要紧，删掉的东西要不回来。

端到端实测（真跑）：

```
当场   danger.rm-secret#2      这个删了，找不回来。 → 别人也找不回来。
他回来 reportBack.dangerRan#2  rm .ssh。 → 它干了。你要不要看看。
```

> 顺带修掉一个早就坏掉的时刻：原来的 `comeback` 用「多久没收到 hook」判定他消失了，
> 但 agent 干活时 hook 一直来，于是**等待场景下它一次都没触发过**（日志 9 次开口里 0 次）。
> 现在改成先查账本：有料说 `reportBack`，没料才退回 `comeback`。
> 教训是——**判据要用「他本人有没有说话」，不能用「有没有事件流」**，后者分不清他不在和它在干。

## 她看得见你（`watch.js`）

以前她只会说「又熬夜了」。那不是她冷淡，是她手上真的什么都没有——
台词可用的变量只有「第几次失败」和「几点」。她看不见你在干什么，只能说空话。

现在看得见了。**数据全在 hook 的 payload 里，零积分、零模型调用、零等待**：

```json
{"cwd": "/home/me/code/demo", "tool_name": "Edit",
 "tool_input": {"file_path": ".../data-center/agent.py"}}
{"tool_response": {"exitCode": 1}}     ← PostToolUse 带成败
```

她能拿到：哪个项目、什么工具、改哪个文件、跑哪条命令、成没成、报错是哪一类。

### 为什么不让她读代码（这是设计，不是偷懒）

三条理由，按重要性排：

1. **装懂会翻车。** 说错一句技术判断，她这个人就废了。而「同一个文件改第三遍」
   这种事实，说错的概率是零——只要数对了就是对的。
2. **看懂代码要模型推理。** 每句一次冷启动 ≈ 1 积分 + 3 秒，而且她并没有你的上下文，
   猜出来的东西还不如不说。
3. **人在意的恰恰是行为。** 你不需要她知道你这行逻辑哪有 bug，你需要有人看见
   你已经在这个文件上耗了四十分钟。

所以她的台词有一条硬规则（单测 `[9]` 守着）：**观察类台词必须带事实锚**——
数字或 `{f}`/`{c}` 槽位。否则就退化成「你在忙」，那是废话。

同时区分了两种句子，这是词表拦不住的地方：

```
「正在改 agent.py」   ← 播报，零增量，看三次就腻（禁）
「agent.py 第三遍。」  ← 数数，有增量，只有旁边的人数得出来（许）
```

区别不在提不提文件，在**有没有你看见的事实**。所以旧版那条「不许出现 文件/命令/代码
这几个词」的铁律被换成了「不许播报进度 + 观察类必须带事实锚」。

### 台词怎么填

`voices.json` 里用槽位，不需要为每个文件写一句：

```json
"grind": { "byCount": { "3": [["{f} 第三遍了。", "你不是在改，是在试。"]] } }
```

`{f}` 文件名（不带路径）、`{c}` 命令头（`npm test -- --watch` → `npm test`，
选项和引号里的内容都会被丢掉）、`{n}` 次数、`{p}` 项目名（日期式目录名自动不念）。

### 从数「多少」到数「怎么变」

前面那几个维度（`grind`/`guess`/`blast`）底层只有三个原语：**计数、查表、时钟**。
全是「数多少」，没有一样是「看怎么变」。而 payload 里明明还有大量信息没被用：

| 她手上有的 | 以前 | 现在 |
|---|---|---|
| 动作的序列（改→跑→改→跑） | 没用 | `loop`：交替到第 3 轮才开口 |
| 两次之间的间隔 | 没用 | `rush`：失败后 8 秒就重跑 = 没看结果 |
| 上一次是什么、这次变成什么 | 没用 | `flip`：换了错 = 绕过第一个坑掉进下一个 |
| 动作的**缺席**（一直看、一直不写） | 没用 | `searchOnly`：翻了一堆地方，一行没写 |
| 单条命令挂了多久 | 只数整轮时长 | `stall`：这条命令跑了 7 分钟 |
| 命令的语义 | `rm -rf` 和 `ls` 同等对待 | `danger`：回不去的才喊停 |

生命力不在台词条数，在于她能不能说出**只有当时那一刻才成立的话**。

**`searchOnly` 的判据要特别说一下**：只看「连着读了很多次」会误伤——他啃一个文件啃半小时是专注，
不是迷路。所以要三个条件同时成立：次数 ≥ 12、**跨 ≥ 4 个不同地方**、撑过 3 分钟。
专注时闭嘴，发散时才开口（单测 `[2]` 正反两条守着）。

**`danger` 的判据窄到只剩一条**：这一步做完，有些东西就**再也回不来**。

```
会说：rm -rf ~ / * / .. / .git / .env    git reset --hard / clean -fdx / push -f    DROP TABLE
不说：rm -rf node_modules / dist / build / __pycache__ / .venv / tmp      ← 删构建产物是正常工作
不说：echo "git reset --hard"        grep -r "DROP TABLE" migrations/     ← 他只是在聊这条命令
```

第二组是关键：判据不是「命令里出现了危险字符串」，而是「**段首就是那条命令**」。
否则你写文档提到 `git reset --hard`，她就冲你喊停——那样她这个人就废了。
单测里 23 条该报、23 条不该报，一对一钉着。

而且 `danger` 只说明「回不去」，绝不推断后果。她**没有**读过你的代码，
所以她不会说「这会删掉你的训练数据」，只会说「那个目录里有什么，你说得出来吗」。

### 节奏（`config.json` 的 `watch`）

| 观察 | 门槛 | 去重 |
|---|---|---|
| `danger` | 认得那几种回不去的命令 | 同一类危险 5 分钟 |
| `flip` | 换了一种错（15 分钟内、同项目） | 同一种换法 10 分钟 |
| `rush` | 同命令失败后 15 秒内重跑 | 20 分钟 |
| `loop` | 改→跑 交替 3 轮 | 20 分钟 |
| `grind` | 同一文件第 3/5/8 次（半小时窗口） | 同一文件 8 分钟内不重复 |
| `guess` | 同一条命令第 3/5 遍（20 分钟窗口） | 同一命令 20 分钟 |
| `blast` | 一轮 6 个文件 | 一小时一次 |
| `errKnown` | 认得的错误类型 | 同一类型 20 分钟 |
| `searchOnly` | 12 次 / 4 个地方 / 3 分钟 | 40 分钟 |
| `stall` | 单条命令 5 分钟 | 30 分钟 |

只有「写」类工具算原地打转。**反复 Read / Grep 同一个文件不算**——
那是你在翻资料，不是打转。这条区分很重要，否则她会在人正常查代码时开骂
（单测 `[2]`、`[15]` 各有一条守着这个）。

认错错的 8 类：缺包、语法、端口占用、权限、命令不存在、超时、测试红、运行时异常。
认不得就**闭嘴**，交给 `repeatedFailure` 报数——宁可少说，不能说错。

## 她会停下来想一下（`brain.js`）

到这里为止，她所有的感知都是**规则**：数次数、认错误类型、看间隔。零成本、零延迟，
但天花板很硬 —— 规则只会数，不会读。她永远说不出「它在第 42 行说 None」，
因为那需要真的把报文读一遍。

所以这一层补的是**深思**，不是替换直觉。分工划得很死：

> **规则决定「要不要开口」—— 所以她的打扰频率一点没变。
> 模型只决定「这一句能说多深」—— 所以只有少数几句会变深。**

这个划法不是省钱，是必须：让模型来判「该不该说话」，等于每一千次工具调用问她一千次，
既贵又慢，还会把她的节奏搞乱。

### 只有四个时刻值得花钱

判据不是「重要」，而是**规则做不了、而卡里恰好有素材**。缺一条就退回去 —— 那不是遗憾，是正确。

| 时刻 | 触发 | 她手上多出来的东西 | 她能说出规则永远说不出的话 |
|---|---|---|---|
| `readErr` | 命令失败且报错正文 ≥160 字 | 报错原文（尾部 1600 字） | 「第 10 行。get 回来的是 None。」 |
| `seeDiff` | 同一文件第 5 次 / 换错 / 秒重跑，且工作区有未提交改动 | `git diff`（≤2600 字） | 「x 从 1 改成 2，多了一行 y。」 |
| `plan` | 一轮动 6 个文件 / 翻了半天没写 | 文件名、命令、他最近两句话 | 「像是把 watch 并进 noverify。」 |
| `dig` | **不挑时刻**：只要动作时间线 ≥3 步 | 时间线 + 每一步的间隔秒数 | 「四秒一次，三次。」 |

**`dig` 为什么不挑时刻了**（这是一次被数据推翻的改动，留档）：

最早 `dig` 只放行 `loop` / `longRun` / `repeatedFailure@5` 三个时刻，判据看着很克制。
跑了几天查 `brain-log.jsonl`，24 次评估里 **14 次 `not-worth-it`，而且 9 种形态全是 `grind`** ——
他日常最常撞上的时刻根本没有路。等于这条路在真实使用里是死的。

根源是判据绑错了素材：`readErr` 要报错正文、`seeDiff` 要未提交 diff ——
**这两样经常是空的**（不在 git 仓库、改完就提交、报错太短）。
而**动作时间线是卡里唯一永远不空的东西**：只要他动过就有。

所以改成：时间线 ≥3 步就看形状（`minDigActions`），陪伴类时刻除外 ——
深夜、他回来了、打招呼这些没有「它在干活」的形状可看，花钱只会买回一句废话。

**这几件永远不深思**（防止以后有人好心加进来）：
`danger`（救命的话不能拖 3 秒）、`lateNight` / `comeback` / `firstGreet` / 自言自语等陪伴类。

### 三道闸：宁可不说，不能说错

她这个人设唯一值钱的地方是**说的一定是真的**，所以「装懂」必须被结构性地挡住。

1. **提示词**：只许说卡里写着的。卡里没有的文件名、函数名、变量名、行号，一个都不许编。
2. **`guard()`**：从输出里抽出每个「代码形状」的东西（`a.py`、`np.array`、`第 42 行`），
   逐个回到事实卡里查。查不到 → 整句作废。**这是可测的、确定性的，不靠感觉。**
3. **体裁**：超过 40 字、带感叹号、带「建议/你可以试试」、带代码块、带括号补注、三句以上 → 作废。

任何一道不过就**静默退回规则那句**（规则那句已经在播了，什么都不用做）。
不重试 —— 重试就是再花一次钱买同一个错。

### 两段式：先甩一句，顿一下，再补一句

模型要 2.5~5 秒（实测）。让她等这 5 秒再说 = 她已经错过了你抬头的那一刻。
所以顺序是：**直觉立刻说**（「运行时报错。」）→ **深思稍后补**（「第 10 行。」）。

这不是工程妥协，人就是这样说话的。等待期间她**不会走开**：气泡顶一个「…」，
配上思考的动画 —— 同一段空白，「…」读作「她在想」，什么都不读作「卡了」。

### 预算（`config.json` 的 `brain`）

| 闸 | 默认 | 为什么 |
|---|---|---|
| `maxPerHour` | 3 | 硬上限。正常运行一天不到 20 次 |
| `minGapMs` | 100 秒 | 两次深思之间至少隔这么久 |
| `sameAnchorHours` | 12 小时 | 同一件事（同文件/同错）说过就不再花钱 |
| `softTimeoutMs` | 9 秒 | 这么久一个字没吐出来就放弃（实测常态 2.5~5 秒） |
| `holdMs` | 14 秒 | 等待期间她站在桌上不走 |

### 实测量到的三个坑（都是真金白银）

1. **CLI 会干等 stdin 3 秒。** `execFile` 给的 stdin 管道永远不关，claude 先等 3 秒才开工
   （stderr: `no stdin data received in 3s`）。改成 `spawn` + `stdio: ['ignore','pipe','pipe']`
   之后，从 9 秒掉到 **2.4~3.0 秒**。一半的延迟是白烧的。
2. **`deepBusy` 卡死会让她永久哑掉。** 只要一次 think() 的 promise 没 resolve，
   `finally` 就没机会执行，此后**她再也不会深思，日志里连一行都不留**。
   现在带超时兜底 + 跳过也记账。
3. **被闸门拦掉的观察不能算「说过了」。** 原来 `_cue` 一发现就记时间戳，
   于是冷却中/预算用完时被吞掉的那次也算说过了 —— 你接下来 20 分钟再犯同样的错，她一个字都不提。
   现在只有真的说出口才 `commit()`。

## hooks 联动

启动器会把事件桥装进 `~/.workbuddy/settings.json`（兼容 Claude Code 的格式），
订阅 13 个事件。**但订阅 ≠ 反应**：绝大多数事件她什么都不做，只是让闸门统计一下
（失败几次、这轮跑了多久、你多久没出现）。真正会让她出场/开口的只有「她家 cwd」和上表那几个时刻。

装的是**全局** hooks，对你所有会话生效——但她只在两种情况下露面：事件来自她家目录，
或者她自己的闸门觉得值得开口。**别的会话里的普通操作不会把她叫到桌面上。**

桥里三条硬规矩（都踩过坑）：

1. **必须 exit 0** —— 否则阻断工具调用。
2. **路径写死绝对路径** —— hook 由 agent 派生，环境里既没 `$HOME` 也可能没 `node`。
   用 `$HOME` 在那样的环境下静默变成空字符串，整个桥失效。
3. **事件不能丢** —— 她冷启动要几秒，这段时间的事件排队补投。
   否则「你在她家说的第一句话」正好会被丢——而那正是最主要的召唤入口。

还有一条自愈：投递失败说明她其实已经死了（强杀/崩溃留下僵尸端口文件），
桥会清掉残留，下一条事件重新拉起她。**不会出现「她永久消失」这种状态。**

```bash
cd ~/.workbuddy/pet
python3 install-hooks.py status      # 看装了什么、桌宠是否在跑
python3 install-hooks.py install     # 重装（幂等，只动自己的 hook，不碰别人的）
python3 install-hooks.py uninstall   # 卸干净（同样只删自己的）
```

单次 hook 开销：她运行时约 **5ms**，没开时约 **4ms**。

## 已知限制

- **她在场时，360×380 的透明区域仍然会挡住下层窗口点击**（没做点击穿透）。

- **她不在时不能被"叫"到——只能被 hook 唤醒。** 你在 WorkBuddy 里点开她家说话，
  hook 会把她叫出来；只想要她在桌面上先露个脸，手动跑一次 Electron 也行（见上一节的启动命令）。
- **她不会思考。** 桌宠这边是规则 + 语料库 + 待说清单（零 token、零延迟）。
  真正会思考的那个她在 `~/WorkBuddy/dafeiyu` 的会话里，走 WorkBuddy 内置额度。
  两边的性格靠同一份 `AGENTS.md` 对齐：**她当场说的话是死的，她提前想好的话才是活的。**

- **她可能安静到让你以为坏了**。这是设计：一天说 20 句你第 5 天就不看了，
  一周说 3 句但句句戳中你才会等她开口。

- Electron 被强杀会留下 `Singleton*` 残骸，桥在拉起前会清，无需手动处理。

## 她的账本（积分）

她住在 WorkBuddy 里，吃的自然是 WorkBuddy 的积分。右键 →「积分累计使用」，
她会先"吃 Token"（数字从 0 滚上去），再掏钱袋给你看：

```
        2.5 分
  3 句 · 平均 0.84 分/句
  WorkBuddy 全局 2358 分
```

钱袋动画按累计消耗分级（`config.json` 的 `ledger.tiers`）：花得越多，袋子越空
（钱袋满溢 → 钱袋如常 → 数金皱眉 → 分文不剩 → 袋空如洗）。

**数据从哪来**：`~/.workbuddy/workbuddy.db` 的 `session_usage` 表，
`credit_json` 字段是 `{消息id: 积分}`。用 Electron 自带的 `node:sqlite` 只读打开，
不写一个字节。她这个工作区（cwd 在 `~/WorkBuddy/dafeiyu` 下）的会话算她的。

### 为什么"一句短话"会比"一整天开发"还贵

实测数据（她自己的第一次对话，4 次 API 调用）：

| 调用 | 输入 token | 命中缓存 | 这一轮积分 |
|---|---|---|---|
| 第 1 次 | 37142 | 128 | **1.26** |
| 第 2 次 | 40201 | 37376 | 0.06 |
| 第 3 次 | 40907 | 40704 | **1.19** |

**差 20 倍，全在缓存上。** 冷启动要全价重付那个 37k 的固定前缀
（WorkBuddy 系统提示 + 工具定义 + 她的 `AGENTS.md`）；热轮次只付增量。

而缓存会不会命中，几乎只取决于**你上一句隔了多久**（全库 8442 次调用的统计）：

| 与上一句的间隔 | 冷调用占比 |
|---|---|
| < 30 秒 | 0.4% |
| 30 秒 – 2 分 | 1.7% |
| 2 – 5 分 | 8.2% |
| 5 – 15 分 | 18% |
| 15 – 60 分 | 40% |
| > 1 小时 | **88%** |

所以：开发一整天不觉得贵（轮次密集、96% 命中缓存），
"隔一小时问一句话"最贵（几乎每次都是冷启动）。想省钱就**一口气说完、连续聊**，
别把对话切成一小时一句的碎片。

## 她为什么回得慢（实测拆解）

从她自己的转录里量出来的，两轮对话的每一段耗时：

| 阶段 | 第 1 轮 | 第 2 轮 |
|---|---|---|
| 你发出消息 → 客户端文件快照 + 生成标题 | 3.0s | 2.7s |
| 模型调用 1（冷 prefill 37k + 228 字推理 + 决定调工具） | 2.4s | — |
| Bash 执行 + 模型调用 2（她跑去看记忆） | 0.9 + 2.3s | — |
| **模型调用 3：推理 1113 字 → 正文 37 字** | **7.5s** | — |
| **单次调用：推理 1207 字 → 正文 22 字** | — | **8.4s** |
| 合计 | **17s** | **11s** |

**她每轮写 1100~1200 字的内心独白，最后只说 22~37 字——比例 30:1。**
串行生成的思考 token 就是全部的慢，正文几乎不花时间。

三个杠杆，按实测收益排序：

| 杠杆 | 省多少 | 怎么做的 |
|---|---|---|
| **不让她为了记东西多跑一趟** | 每次工具往返 2~5s | 日记改由桌宠抄（`journal.js`），读转录零积分 |
| **不让她重复读记忆** | 第 1 轮 **-5.6s** | `MEMORY.md` 本来就每轮注入（`<working_memory_content>`），AGENTS.md 里明写「别再 ls / 别 Read」 |
| **压推理长度** | 每轮 -3~4s | AGENTS.md「别把时间花在犹豫上」：第一个不犯忌的说法就说出去 |

两条走不通的路，别试：

- **关掉思考**：`deepseek-v4.1-flash` 的 `thinkingLevelMap` 是 `{minimal:null, low:null, medium:null, high:"high", max:"max"}`——只有 high/max，没有"关"。
- **换个更快的模型**：换模型会让提示缓存全冷（实测 77% 概率），反而更慢更贵。

## 她的活人感：复读 + 连说几句 + 待说清单

**① 复读（`echo.js`）：她说什么，桌面上那只鱼就说什么。**

这是最重要的那条。原来桌宠只在「时刻」说话（你回来了、你连着失败三次、坐太久），
于是**你正经跟她聊天的时候，桌面上反而一个字都没有**——她刚在聊天窗口说完
「去吧。下次回来我不一定开门。」，屏幕角落那只鱼却一声不吭，看着像个哑巴挂件。

现在的链路：

```
她回复完（Stop）→ hook payload 带 transcript_path
  → 读本地转录，取她最后一条回复（遇到你那句就停）
  → 按她的换行拆成最多 3 拍 → 气泡一句一句蹦出来
```

- **零积分**：读的是本地 jsonl，不调模型
- **拆拍用她的换行**：她本来就爱分段，一个换行就是一个停顿
- **最多 3 拍、单拍 60 字**，后面还有话就在末拍加「…」，不假装说完了
- markdown 会被剥掉（`**`、反引号、列表点、代码块），气泡里是纯文本
- 只有她在**她家**（`~/WorkBuddy/dafeiyu`）说完才复读。你在别的项目干活，她不念
- `config.json` 的 `echo.enabled` 可关，`maxBeats` / `maxChars` / `anim` 可调

> 格式坑（踩过两次）：转录里 `message` 字段往往只装 `usage`，正文在**顶层** `content`；
> 文本块类型叫 `output_text`，不是 `text`。第一版按「标准格式」读，读真实文件永远是空串——
> 单测全绿，实际一句话都不出。`echo.test.js` 有一条就是专门守这个格式的。

**② 连说几句（`voices.json` 写成数组）。** 台词写成数组，她就会拆成几句说，
中间带停顿和一个「…」：

```json
"lateNight": { "lines": [ "{clock}了。", ["不早了。", "我不劝你。", "我劝过。"] ] }
```

一条一句的是"朗读器"，一条两三句的才像人。这是零成本的，但效果比任何模型都直接。

**③ 待说清单（`thoughts.jsonl`）。** 规则生不出见地——见地必须来自真的读过上下文。
所以位置放在她真的读得懂的地方：**她自己在 WorkBuddy 会话里想好，写成纸条**，
桌宠只负责在对的时机念出来。

```
~/WorkBuddy/dafeiyu/.workbuddy/thoughts.jsonl
{"text":"那个还没结论的事，你昨晚也在想它。","at":1792982782785}
```

- 她在会话里想好就写（`AGENTS.md` 有约定：一次 1-2 条、20-30 字、必须有具体指向）
- 桌宠在「你刚提问」或「你刚收工」时偶尔弹一条出来，同样吃小时预算（一小时八次封顶）
- 念过就划掉（记在 `thoughts.seen.json`），一周没说出来自动作废
- **零额外积分**：想这些话用的是那次对话本来就付过的 token

和"给桌宠接模型"比，差别是：接模型每句都花钱且它没有上下文；
待说清单不花钱，而且写的时候她手边就有 memory 和全部前情。

## 为什么改（前两版的死因，留档）

**形态一**：「工作伴侣」。agent 调工具 → 她敲电脑；工具报错 → 她垂头；完成 → 撒花。
问题不在实现，在**它的技术底座天然是全量广播**：hooks 写在全局 settings 里，每个事件都上报，
于是你在任何窗口做任何事，她都在跳。全量广播 + 表情映射 = 噪音发生器。
而且她卖的是**信息**，信息必然习惯化——看得懂的东西第三次就不看了。

**形态二**：她常驻右下角，说不出话也不打扰，靠时刻表偶尔开口。
问题是常驻本身：她一直在那儿，就成了桌面上的一个挂件；你干活时她在那儿洗澡、打哈欠，
久了你会觉得"有点吵"而不是"有点暖"。

**形态三**（当前）：卖的是**关系**，而关系需要**期待**。
她不在的时候你才可能想她；她一直在的时候你只会想关掉她。
所以现在是：你来她才来，你走她就走。
